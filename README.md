# Yggdrasil

无限派生。一个输入框，长出一整片森林。

用户输入自然语言，基底 Agent 调用 LLM 把它翻译成**声明式派生指令**，前端执行这些指令，
派生出新的组件、工具、Agent，或者改写整页样式。派生出的组件是桌面上可拖拽、可缩放、
可隐藏/关闭/删除的窗口。

## 运行

```bash
pnpm install
pnpm dev
```

构建：

```bash
pnpm build     # tsc --noEmit && vite build
pnpm preview
```

首次打开后，点输入窗口标题栏右侧的 `⚙`，填入 OpenAI 兼容端点的 Base / Key / Model。
密钥存在浏览器本地存储里，不经过任何后端。

## 用法

输入窗口的标题栏可拖动，右下角可缩放，位置会持久化。输入任务后 Enter 提交：

| 输入 | 结果 |
| --- | --- |
| `生成一个计算器` | 派生出计算器组件，作为窗口插入桌面 |
| `切换到霓虹风格` | 改写全局 CSS 变量，整个页面变成霓虹色（不产生任何节点） |
| `做一个能自己盯盘、定时汇报的助手` | `create_component` + `agent` 接入能力；外观仍由组件自己的源码决定 |
| `做一个把数字翻倍的工具` | 注册一个可被调用的工具 |
| `把那个计算器的标题改成"加法机"` | 用 `update_component` 改已有组件，不新建 |
| `把窗口标题栏换成极简风格` | 用 `replace_surface` 替换界面插槽 |
| `先看看现在界面上有什么` | 用 `inspect` 读结构，再进入下一轮动手 |
| `抓取 example.com 并总结` | 用 `fetch_url` 联网取回正文再处理 |
| `在计算器里挂一个 Agent` | 用 `attach_agent` 给那个组件接入能力 |
| `把计算器最小化` | 用 `set_window_state` 收起窗口，可从任务栏恢复 |
| `你好` | 同样要派生 —— Agent 会建一个窗口来回应，因为它无法直接说话 |

### 发送队列

Agent 思考时输入框**不会锁死**：这时提交的内容会排队，当前任务一结束就按先来后到自动发送。

- 队列显示在输入行上方，每条带序号；不是发给基底的条目还会标出目标 Agent。
- 每条右侧 `✕` 单独移出队列，被移出的**不会执行**。
- 忙碌时发送键从实心 `↑` 变成描边 `⇥`，一眼能看出这次是"排队"而不是"立刻发"。
- 队列出现时输入窗口自动长高（最多两项，再多在队列框内滚动），清空后自动缩回。
- 队列**不持久化**：刷新页面不会把旧指令补跑一遍。
- 排队期间目标组件被删掉的条目会被丢弃并记一条日志，**不会改发给基底**。
- 每次出队都会在日志里留一条 `queue → …`，排队项到底有没有被发出去可以直接查。
- **中文输入法用回车确认候选词，不会触发发送**（拼字期间的回车一律忽略）；
  提交时读的是输入框的当前内容而不是 React state，并且**确认收下才清空** ——
  所以不会出现"打好的字被吞掉"或"又发了一遍上一条"。

一次只跑一个任务 —— 输入框与组件里 `useAgent().send()` 走的是同一条串行队列。

页面**右上角**固定四个按钮：`≡`（执行轨迹，带步数角标）、`☰`（节点检查器）、`⚙`（LLM 设置）、
`⟲`（重置）。重置会清除全部节点、窗口、轨迹、排队中的输入与样式变量，只保留 API 设置，需二次确认。

## 窗口

派生组件、Yggdrasil 输入框、节点检查器、执行轨迹、LLM 设置都是可拖动窗口。
输入框默认只有一行高、贴底居中，内容多了会**自己长高**（最多 6 行，窗口跟着长，清空后缩回）；
把窗口手动拉高时，输入区会**填满**那块空间而不是缩成一行贴在底部。
有排队消息时窗口按队列条数增高（最多两行）。窗口以底边为锚向上长，不会顶出屏幕底部。
窗口与面板都随视口**按比例缩放**：调整浏览器大小时，整个桌面跟着缩放，
窗口之间的相对布局保持不变（最小化 / 关闭的窗口也一样）。
缩到很小（约 160×90）后会被下限兜住，再放大回原尺寸时这些窗口不会精确复原。

标题栏右侧按钮：

- `–` 最小化：窗口**缩小并飞向左下角任务栏**，落到位后才收起（**保留运行状态**）。
  点任务栏上的名字恢复时走反向动画：窗口从任务栏的位置**长回原位**。
  节点检查器里的状态按钮切到"最小化"走的是同一套动画。
- `✕` 删除：从派生树摘除，**级联删除其所有子孙节点、挂载的 Agent 与派生工具**，不可恢复。

最小化与关闭过的窗口都会在桌面左下角留一个任务栏条目，点一下就能回来 —— 最小化回到原状态，
关闭则重新实例化。

**层级只有一个规则：点谁谁在最上层。** 输入框、Trace、设置、检查器这些自带面板与派生组件
渲染在同一个容器里、共用同一套层级，没有谁天然置顶。

**Agent 能像操作浏览器一样操作这些窗口**：新建（`create_component`）、关闭（`remove_node` 或
`set_window_state`）、查看（`inspect`）、调整（`update_component` 的相对位移 / 居中 / 铺满 /
贴边 / 置顶，几何结果自动夹进视口）、批量排布（`arrange_windows`）。
Agent 知道当前视口尺寸，所以算坐标不用猜。

面板的初始层级刻意低于派生组件，所以新生成的窗口默认盖在面板上；点一下面板，它就会升到最上面。

节点检查器只放**节点树**：每个组件有 `✎`（用自然语言改版，编译通过才落盘）、`</>`（查看源码），
以及一个状态按钮在 显示 / 最小化 / 关闭 之间循环。运行日志在 Trace 面板里。

## Agent

**Agent 不是窗口，也不是另一种组件 —— 它是挂在组件上的一份能力。**

- 基底 Agent 是唯一那个 `root` 组件：`scope` 为 `*`，不渲染成窗口、不进任务栏。
- 任一普通组件的 `agent` facet 就是"子 Agent"：它有自己的上下文、职责与作用域，
  可以在自己的界面里继续用同一套接口往下创建组件与 Agent。

这就是"无限派生"的形态：不是一条 Agent 链，而是能力挂在组件上、组件又能长出新的带能力组件的树。

### Agent 是"能力"，不是界面

**Agent 不是一种窗口，也不是另一种组件 —— 它是一种能力。**

把一个组件的 agent 能力接上，这个组件就获得了自己的上下文、职责与作用域，能自己思考并行动。
**它长什么样和有没有这种能力完全无关。**

- 组件永远只有**一份源码**：它自己的 `source`。界面只由它决定。
- **agent 能力不携带任何界面。** 没有"agent 专属的界面"这种东西。
- 所以接入 agent 后窗口**不会**自动出现聊天框、消息列表或输入框。

怎么用：

**创建 Agent 没有单独的入口 —— 它就是创建一个带 agent 能力的组件。**

| 目的 | 做法 |
| --- | --- |
| 创建带能力的组件（= 派生 Agent） | `create_component` 带 `source`（界面）+ `agent`（能力） |
| 给已有组件接入能力 | `attach_agent` 带 `id` —— **界面不变** |
| 移除能力 | `detach_agent` |
| 改职责 / 作用域 / 工具 | `set_agent_config` |

有能力与没能力的组件**在渲染上完全一致** —— 不贴标签、不换外观。

`agent` 里只放能力：`systemPrompt`（职责）、`tools`（工具子集）、`scope`（作用域）。
**没有 source。**

### 什么时候该接（默认不接）

**agent 能力是重武器，默认不接。** 多一次模型调用、多一份上下文、多一层作用域限制，
一个本来只是"把东西显示出来"的组件接上它，只会变得又慢又绕。

只有下面任一情况成立才接：

1. 用户明确要求「一个能自己…的助手 / agent / 机器人」；
2. 用户要求这个组件**持续自主运行**（定时刷新、盯着变化、自主决定下一步）；
3. 用户要求它**自己接收后续输入并独立决策**，而不是由你一次性做完。

拿不准时**不要接** —— 先做普通组件，之后想让它动起来再 `attach_agent`。

与 agent 无关的请求就更是如此，例如：

| 请求 | 做法 |
| --- | --- |
| 「上网搜集新闻」 | `fetch_url` 抓取 + `create_component` 渲染成列表（**普通组件**） |
| 「做个计算器」 | `create_component`（普通组件） |
| 「生成一个日历」 | `create_component`（普通组件） |
| 「把背景换成 WebGL 动画」 | `replace_surface`，与 agent 无关 |

为了不依赖模型自觉，执行器还有一道闸：

- `create_component` 的 `agent` 字段必须是**有实质内容**的（至少一条 `systemPrompt` 或一组 `tools`）。
  空壳 `agent: {}`、只写了 `scope` 的、`systemPrompt` 全空白的，一律**忽略**，并在返回信息里说明。
- `attach_agent` 同样要求职责或工具，否则直接拒绝。

### 在界面里使用这份能力

能力要在界面上体现出来，**得你自己在源码里渲染**：

```tsx
import * as React from "react";
import { useAgent } from "yggdrasil";

export default function Weather() {
  const a = useAgent();   // { id, name, host, messages, running, role, send, clear }
  const [city, setCity] = React.useState("");
  return (
    <div style={{ display: "flex", flexDirection: "column", height: "100%" }}>
      <input value={city} onChange={(e) => setCity(e.target.value)}
             onKeyDown={(e) => { if (e.key === "Enter") { a.send(city); setCity(""); } }} />
      <div style={{ flex: 1, overflow: "auto" }}>
        {a.messages.map((m, i) => <div key={i}>{m.content}</div>)}
      </div>
    </div>
  );
}
```

呈现方式没有规定 —— 聊天框、按钮排、表格、卡片都行（"触发器 Agent" 可以只有两个按钮，
"看板 Agent" 可以直接渲染表格）。

### 用了 useAgent 就必须有能力

**源码里一旦 import 或调用 `useAgent`，这个组件就必须接入 agent 能力。**

如果没接入：

- `a.send()` 是**空操作** —— 消息不会发出去，**也不会替你转给基底 Agent**；
- 控制台会打印一条警告说明原因；
- `a.attached` 为 `false`，`a.id` 为 `null`（不是 `'root'`）。

之所以要这么严格，是因为早期版本里"未接入"会退回基底 Agent，消息被静默收走，
从界面上完全看不出来。现在这种情况会立刻暴露。

好消息是通常不用手动处理：**`create_component` 与 `update_component` 检测到源码里同时出现
`from "yggdrasil"` 与 `useAgent` 时会自动接入能力**（创建时的返回信息里会注明）。
只在一句注释里提到 `useAgent` 不会触发。

### 作用域是硬约束

`scope` 是代码层的约束，不是提示词建议。越界操作会被执行器直接拒绝：

- 改别的组件、删别的组件、给别的组件改样式 → 拒绝
- 改全局样式（`update_theme`）、替换全局界面插槽（`replace_surface`）→ 拒绝
- 改自己 → 允许

基底 Agent 也只是一个"接了 agent 能力的组件"，区别是它 `scope` 为 `*` 不受限、
且不作为窗口渲染（不出现在桌面、不进任务栏、不能被 `update_component` 当成目标）。

## Agent 接口层

Agent 能做的事是一张**可扩展的接口表**，不是写死的几个分支。一个接口就是一条指令类型，
注册进 `src/kernel/registry/interfaceRegistry.ts` 即可被 Agent 使用 —— 总线本身不认识任何具体
kind，它只查表、调用 handler。

| kind | 作用 |
| --- | --- |
| `create_component` | **新建页面/窗口**。默认（也是唯一）的创建入口；`agent` 字段可选且默认不写 |
| `update_component` | **调整窗口**：换源码 / 改标题 / 显隐 / 层级 / 局部样式；几何支持绝对 `pos``size`、相对 `dx dy dw dh`、`center``fill``align``focus` |
| `set_window_state` | 按 id 或名字设置窗口为 显示 / 最小化 / 关闭 |
| `list_nodes` | 按名字或类型查找节点，返回 id、位置、状态、是否挂了 Agent |
| `create_tool` | 派生工具并注册 |
| `call_tool` | 调用工具取值 |
| `attach_agent` | 给已有组件接入 agent 能力（界面不变），必须给出 `systemPrompt` 或 `tools` |
| `detach_agent` | 移除组件的 agent 能力 |
| `remove_node` | 级联删除节点 |
| `update_theme` | 改写全局 CSS 变量 |
| `set_node_tokens` | 只改写某一个节点的局部样式变量 |
| `inspect` | 读取界面结构：窗口 / Agent / 节点树 / 样式变量 / 插槽 / 工具 |
| `set_agent_config` | 改某个 Agent 的名字 / 职责 / 作用域 / 工具子集 |
| `clear_agent_context` | 清空某个 Agent 的对话历史 |
| `arrange_windows` | **批量排布窗口**：`grid` 网格 / `cascade` 层叠 / `stack` 居中叠放 |
| `fetch_url` | 抓网页，返回正文、**图片直链**与可跟进的链接 |
| `fetch_image` | 验证图片直链可达性与类型（HEAD，不下载正文） |
| `list_surfaces` | 列出可替换的界面插槽 |
| `replace_surface` | 替换非关键插槽（**会持久化**）；关键插槽会被拒绝 |

新增能力只要写一个 `AgentInterface` 并注册，**提示词与校验都会自动跟上** —— system prompt
里的接口清单、示例、以及"kind 只能取这些值"的约束都由注册表生成。

### 界面插槽

界面被拆成具名插槽，Agent 可以用自己的组件替换其中任意一个，把 source 传 `null` 则还原内置实现：

| 插槽 id | 元素 | 可替换 |
| --- | --- | --- |
| `window.titlebar` | 每个窗口的标题栏 | **否（关键插槽）** |
| `desktop.background` | 整页背景 | 是 |

**关键插槽不可替换。** `window.titlebar` 承载窗口的基础能力（拖动、最小化、删除），
`replace_surface` 会直接拒绝它。想改窗口外观请用 `update_component` 改名字/位置/尺寸，
或用 `set_node_tokens` 调它的配色。

插槽组件会收到该插槽约定的 props。新增插槽：在 `src/host/surfaces.ts` 注册，
并在渲染处用 `<Surface id="..." fallback={...} />` 包住内置实现。

## 联网

`fetch_url` 抓一个网址，返回四样东西：正文文本（HTML 会被剥标签）、**图片直链**、可跟进的链接，
以及 `via`（走的是直连还是代理）。

- 直连被 CORS 拦掉时会自动回退到渲染代理（`r.jina.ai`）。代理返回的是 markdown，
  链接与图片照样会被抽出来 —— 这条路径以前是一条链接都不返回的。
- **图片直链**从 `<img>` 的 `src / data-src / data-original / srcset / og:image / 内联 background-image`
  以及 markdown 的 `![](...)` 里抽，全部补成绝对地址，可以直接写进 `<img src>`。
- **先抽 URL，再裁正文**。`maxChars`（默认 12000，最大 60000）只裁正文，不影响链接与图片数量；
  截断时返回里会写明"共 N 字符，只回了前 M 个"。
- `fetch_image` 先发 HEAD 确认 `content-type` 是 `image/*`；如果返回的是网页或 JSON，
  会明确告诉你"这是详情页不是直链"。
- 提示词里也写了：**别反复抓同一个 JS 画廊页**（像"百度图库"这类页面靠脚本渲染，
  抓到的 HTML 里本来就没有图片地址），优先用返回里的图片直链、og:image 或返回 JSON 的接口。

### 执行结果怎么回到模型

每条指令的 `observation`（正文、图片直链、链接、`inspect` 快照、工具返回值）会**真的**回灌给模型 ——
一行结论 + 具体内容，作为下一轮的用户消息。**观察结果按轮累积**（滚动预算 40000 字符），
所以第 1 轮抓到的页面到第 5 轮还在，多步任务不需要反复重抓。

这部分以前是断的：`formatOutcomes` 只回 `message`，模型看到的永远是
「已抓取 url（正文 N 字符 · 图 M · 链接 K）」这种汇总，正文只在轨迹面板里给人看。
见 dev.md §5.41。

## 可观察性

Agent 的每一步都可查看。

- **查看页面**：`inspect before="windows"` 看视口与全部窗口；`inspect before="component" id=...`
  看某一个页面的几何、状态、样式、是否接入 agent 能力，以及**它的源码**。
- **执行轨迹（Trace）**：输入窗口底栏的 `≡`（或数字）打开 Trace 窗口。每条指令一行，
  带轮次、接口名、下一步摘要、耗时，以及
  `◌` 进行中 / `✓` 成功 / `✕` 失败 的状态标记；模型推理本身也占一行，生成中实时刷新。
- **成败反馈**：一次运行结束后在页面顶部弹一条提示，分三档 —— 全部成功、部分成功
  （带成功/失败计数）、失败（带原因）。4 秒后自动淡出，点击可立即关闭。
- **自动恢复**：出错不会直接停掉。模型调用失败会退避重试；指令格式错误或整轮失败会把原因
  回灌给 Agent 让它换做法重试（上限 3 次）。每次恢复在轨迹里留一条 `自动恢复` 记录。
- **状态栏**：输入窗口底栏实时显示当前阶段，例如 `执行 2/3` 与当前指令摘要。
  输入行默认一行高（88px 的面板），随内容长到 6 行、随队列再多长两项。
- **运行日志**：Trace 面板右上角那个数字按钮切到日志视图，保留完整的运行记录（可清空）。
  与节点树无关，所以它不在 Nodes 面板里。

## Agent 没有直接输出通道

**Agent 不能"说话"。** 它输出的 JSON 只有执行轨迹能看到，页面上没有聊天框、没有消息列表、
没有回复区。它唯一能影响世界的手段就是指令（ops）。

这不是缺陷，是设计：想让用户看到什么，就必须**把东西做出来**。

- 用户问"你能做什么" → Agent 建一个窗口，把能力列进去。
- 任务完成的交代 → Agent 用 `update_component` 把结果写进相关组件的界面。
- Agent 要报错 → 把错误渲染进一个组件；只在轨迹里留一行用户是看不到的。
- 用户只说"你好" → 同样要做点什么，否则界面上不会有任何变化。

相应地，模型如果只回了文字、给不出合法指令，这一轮**判为失败**并在反馈条上说明原因。
「说明:」前缀与聊天特判都已移除 —— 所有输入一律走派生，没有例外分支。

## 样式

样式不是界面上的一个东西，而是**一组可被 Agent 随时改写的 CSS 变量**。没有主题名、没有主题
选择器、没有主题列表，派生树里也不会出现主题节点。Agent 只是在合适的时机调用
`update_theme` 给这组变量赋值，多次调用逐次覆盖。

默认值是扁平化世界树：**金黄色描边 + 暗棕色填充，不加阴影和高光**。边框只出现在窗口根容器上，
窗口内部一律靠留白与底色分层；执行轨迹用一条主干加分支点表示，不给每步套盒子。
桌面背景是一块纯色。

默认指向**扁平与克制**：界面上没有多余的框线，重点靠颜色与位置表达。

- 变量集中在 `src/theme/engine.ts`，`--ygg-shadow` 与 `--ygg-glow` 默认都是 `none`。
- 没有渐变，没有单侧边框：桌面背景是纯色；成败提示与错误面板用整圈描边；Agent 消息条用整块底色。
  **边只出现在窗口根容器这一层，容器内部不画任何分隔线。**
- 只有 `THEMEABLE_KEYS` 里列出的变量允许被改写；动效时长与缓动（`--ygg-t-fast` / `--ygg-t` /
  `--ygg-t-slow` / `--ygg-ease` / `--ygg-ease-out`）不在白名单内，生成指令改不动它们。
- 生成组件的 system prompt 里明确禁止 `boxShadow` / `textShadow` / `gradient` / `backdropFilter`。

### 动效

扁平不等于呆板：界面质感靠**反馈动作**而不是靠阴影渐变。

- 所有可点元素都有三段反馈 —— 悬停（描边回温 / 底色切换 / 位移 1–2px）、按下（轻微缩放）、
  过渡（`--ygg-t-fast` ~ `--ygg-t`，统一缓动）。
- 窗口入场带一点收束缩放；拖动时**关掉过渡**，手感才跟得住指针，且拖动期间不会误选中内容。
- 改样式（`update_theme` / `set_node_tokens`）时整页颜色**渐变过去**而不是硬切。
- 排队项从下方浮起，轨迹步、节点行、任务栏条目都有各自的入场。
- 系统开了 `prefers-reduced-motion: reduce` 时全部动效归零。
- 动效集中在 `src/styles/global.css`：按钮与输入框的 hover / active 过渡、窗口出现与内容淡入、
  聚焦描边变色、滚动条与日志行悬停。时长令牌 `--ygg-t-fast` / `--ygg-t` / `--ygg-t-slow`。
- 尊重 `prefers-reduced-motion`，用户关闭动效时全部动画停用。

扁平化不是限制：`--ygg-glow` 与 `--ygg-shadow` 是真实生效的变量，说"切换到霓虹风格"
就会重新启用发光。

## 架构

```
用户输入
  → Yggdrasil 输入窗口构造请求
  → 基底 / 子 Agent：LLM 调用（system prompt 里带节点树、当前样式变量、工具清单）
  → 返回 DerivationPlan { reasoning, continue, ops[] }
  → 派生总线按 kind 查接口表，逐条执行，每步产生一条 TraceStep
      （kind 不认识就报「未知接口」，并把可用清单回给模型）
  → 回写派生树 + 持久化
  → 若 continue=true，把执行结果作为观察回灌，进入下一轮（**没有轮次上限**）
  → 收尾：统计成功/失败步数，写入 RunFeedback
```

轮次不封顶：只要模型自己说 `continue`，就一轮轮跑下去，直到它给出 `continue: false`。
唯一的兜底是**空转判定**（不是步数上限）—— 连续两轮给出完全相同的指令、又得到完全相同的
结果，说明再跑下去不会有新东西，此时停止并在反馈条上说明。错误重试预算是 3 次。

LLM 不直接操作 DOM，只输出声明式指令；所有副作用由前端执行器完成，因此可以校验、可以回滚
（一轮 ops 全部失败时自动撤销该轮的节点与样式变量改动）。

### 生成代码的约束

LLM 生成的组件必须是 TSX 源码，`export default` 一个 React 组件，只能 `import` react /
react-dom / react-dom/client，样式写成行内 style 并引用 `--ygg-*` 变量以跟随全局样式。
编译在浏览器里由 `@babel/standalone` 完成，`import` 被改写成宿主注入的 require。

**已知限制**：`new Function` 不是安全沙箱，生成代码与宿主同权限。本期接受该限制。

### 升级说明

早期版本的存储里，Agent 是独立的 `kind: 'agent'` 节点。现在的模型里 Agent 是组件的 `agent` facet，
启动时会自动迁移：旧的子 Agent 折叠到它的宿主组件上，旧的基底折叠成带 `root` 标记的组件。

迁移是自动的，但如果你在旧版本里存过比较复杂的结构，建议升级后先点右上角 `⟲` 重置一次，从干净状态开始。

### 存储

IndexedDB 为主（`idb-keyval`），启动时探测读写；探测失败（隐私模式、打开超时等）自动降级到
localStorage 并在输入窗口上显示「回退模式」；两者都不可用时降级为纯内存并提示本次会话不会保存。
派生树、节点源码、消息历史、样式变量、插槽覆写、设置、日志、窗口位置、每个 Agent 的"做过什么"
都持久化，刷新后恢复。

### 不会重复劳动

每个 Agent 有一份 `ledger`：它做过的组件、Agent、工具、插槽替换、样式改动都会记进去，跨刷新保留。
这份记录会进入它的提示词，并明确标注"这些已经存在，不要重复创建"。
所以刷新后再要求添加新东西，它只会做新的那部分，不会把之前的重做一遍。

## 内置工具

基底 Agent 默认可用 `calc`（算术求值）、`now`（当前时间）、`random`（区间随机整数）。
派生出的工具会注册进清单，进入后续所有 LLM 调用的工具表。
